# Coflux 2.21.1

**A workspace whose worktree was already deleted outside Coflux can be deleted again, instead of failing with "is not a working tree".**

Worktrees often disappear without Coflux being involved: an agent cleans up its own worktree when it finishes, a branch cleanup removes it, or you run `git worktree remove` yourself. The workspace stayed in the sidebar, and deleting it failed every time with `fatal: '<path>' is not a working tree`, because Coflux still asked git to remove a worktree that no longer existed.

In 2.21.1:

- Deleting a workspace whose worktree directory is gone succeeds and removes it from the sidebar. This also covers a worktree whose directory was deleted while git still listed it; Coflux tidies git's list as part of the delete.
- If the directory still exists but is no longer a git worktree, the delete still fails and leaves the directory untouched. Coflux never deletes a folder it cannot identify as the workspace's worktree.
- Deleting a live worktree works as before.

## Install or update

**Mac:** install `coflux-2.21.1-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.21.1
cofluxd update
```

## Upgrade impact

- The fix runs on the device that holds the worktree. On a Mac, update the desktop app. A headless host that already runs the launcher receives the new runtime automatically, with terminals kept open; `cofluxd update` does it immediately.
- Workspaces that could not be deleted before can be deleted normally once their device is updated.
- No center, protocol or configuration change.
