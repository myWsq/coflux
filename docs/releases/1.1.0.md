# Coflux 1.1.0

**Claude Code and Codex integration now travels with Coflux.**

Coflux terminals can automatically load agent capabilities and current workspace context from the integration shipped with your desktop app or native CLI. Managed terminals no longer depend on a separate marketplace update for this integration.

## Highlights

- **Keep your usual commands.** Start `claude` or `codex` in a Coflux bash, zsh, or fish terminal. Custom launchers can use `coflux agent run claude -- ...` or `coflux agent run codex -- ...`. Existing user aliases and functions retain priority.
- **Updates without switching active agents.** Each new agent launch uses the installed integration. Running agents retain their own CLI, hooks, and skill files until they exit.
- **Fresh context across long sessions.** Session resume, context compaction, and workspace changes refresh the coordinates available to the agent.
- **Native Codex review.** Codex asks for hook approval when required, including after an integration update. Coflux does not edit global agent settings or approve hooks for you. Use `/hooks` in Codex and `coflux agent status` to inspect readiness.
- **Complete headless delivery.** Signed native CLI artifacts now ship alongside the runtime for Linux and macOS. Built-in hooks do not require an additional Node interpreter.

## Install or update

**Mac:** install `coflux-1.1.0-arm64.dmg` or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:** update both the npm launcher and installed device binaries:

```sh
npm install -g cofluxd@1.1.0
cofluxd update
```

For a new device, run `cofluxd up` and follow the authorization link.

## First-time activation

Automatic shell integration requires the updated terminal runtime. Finish active work before restarting that runtime: a Supervisor restart ends its terminal processes. On headless devices, use `cofluxd restart` after updating; on desktop, use the runtime restart action when your tasks are finished. Then open a new terminal.

A shell opened before this feature was installed cannot acquire the new shell functions retroactively. It can still use `coflux agent run` explicitly. Once the new shell integration is installed, already-open shells pick up later integration updates when you next start an agent.

Updating only the npm package does not replace installed native binaries; run `cofluxd update` as shown above. Worker-only hot upgrades do not update the CLI or shell functions.

To bypass managed integration for one launch, use `COFLUX_AGENT_INTEGRATION=off claude` or `COFLUX_AGENT_INTEGRATION=off codex`. External-terminal marketplace integration remains optional. Existing Codex plugin management stays under your control.

Native acceptance was verified with Claude Code 2.1.269 and Codex CLI 0.154.0. Older hosts without the required hook interfaces are not supported.
