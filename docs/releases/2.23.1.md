# Coflux 2.23.1

**Links in the terminal end where the link ends, and links that a program declares open when you click them.**

Two problems with clicking links in the desktop terminal are fixed:

- A URL followed by Chinese or Japanese text ran on into it: in a sentence like "open https://cchost.ai/docs, then sign in" written in Chinese, everything after `https://` up to the next space, including the full-width comma and the rest of the sentence, was one link, so clicking it opened a broken address. Full-width punctuation such as `，。、：；「」（）【】…` now ends a link, the way it does in VS Code's terminal. A trailing `.`, `,`, `;` or `:` is no longer part of a link either, and a closing bracket stays in a link only when its opening bracket is in the link too. `https://en.wikipedia.org/wiki/Foo_(bar)` stays whole, and `(https://example.com)` loses the outer brackets. Letters written straight after a URL with no punctuation between them, such as a Chinese page name in a Wikipedia address, still belong to the link.
- Links that a program marks up itself (OSC 8 hyperlinks, which some agent CLIs and tools print) showed an English "Do you want to navigate to …?" dialog, and then nothing opened. They now behave exactly like any other link: a click opens it in your browser with no dialog, hovering shows the hint, and the right-click menu offers to open it in the system or built-in browser, or to copy it.

## Install or update

**Mac:** install `coflux-2.23.1-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.23.1
cofluxd update
```

## Upgrade impact

- The change is in the desktop app only. Update the desktop app to get it; headless hosts gain nothing new from this release.
- No center, protocol, runtime or configuration change.
