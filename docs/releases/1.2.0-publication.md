# Coflux 1.2.0 publication record

Published on 2026-09-12. Release commit: `ba537dddb3dbde71ddbf7ffc9ea0f965ca20fdea`.

- [Main CI](https://github.com/myWsq/coflux/actions/runs/34703878100): successful.
- [Unified release](https://github.com/myWsq/coflux/actions/runs/34704301699): successful.
- [Stable release](https://github.com/myWsq/coflux/releases/tag/v1.2.0): published, neither draft nor prerelease; 40 assets.
- Desktop update feed: `latest-mac.yml` on `desktop-updates` advanced to 1.2.0.
- [npm publication](https://github.com/myWsq/coflux/actions/runs/34705157036): **failed on both attempts; `cofluxd@1.2.0` was never published.** npm `latest` remains 1.1.1.

Artifact acceptance beyond the workflow's own signing, notarization and verification steps was not performed for this version. The 1.1.0 acceptance procedure is recorded in [1.1.0-acceptance.md](1.1.0-acceptance.md).

## Why npm was not published

The npm gate reuses `ci.yml` from the **default branch** while checking out the **release commit**. Pull request #50 merged into main minutes after `v1.2.0` was tagged, and it added a `ci.yml` step that runs `scripts/check-protocol-breaking.mjs`. That script does not exist in the 1.2.0 tree, so the gate failed with a missing module and the publish job was skipped.

`ci.yml` now skips that script and its unit test when the checked-out commit predates them (`4a4acd82`), which prevents the failure for later releases. Re-running the failed npm workflow does not pick the fix up: GitHub re-runs a workflow with the workflow files captured for the original run. A repaired gate only takes effect in a new `npm-publish` run, and the only trigger for one is a successful `release` run.

No recovery was attempted, because re-running the release workflow would rebuild, re-sign and overwrite already published artifacts, and the desktop update feed rejects content changes for a version it already carries. `npm-publish.yml` deliberately offers no standalone publication entry point.

## Consequences

- Desktop installations are unaffected: they update from the GitHub Release through the desktop feed.
- Headless devices update with `cofluxd update`, which installs and verifies this release's native components through an existing launcher. Only `npm install -g cofluxd` on a brand-new device yields the older 1.1.1 launcher, which then installs 1.2.0 components normally.
- The npm package contents for 1.2.0, including its copy of the agent skill, are not on the registry. The next successful release publishes the npm package again and closes the gap.
