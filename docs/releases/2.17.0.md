# Coflux 2.17.0

**Coflux now connects to `api.coflux.yourantiandi.com`, a server in mainland China.**

The Coflux server, its database and the relay used for remote connections moved to a host in Shanghai on 2026-10-09. Its new address is served directly from mainland China; the old `api.coflux.dev` address still works, but it now passes through Cloudflare and a forwarder in Japan, which takes about 1.9 seconds per request instead of about 0.1 seconds.

This release makes the desktop app, the iOS app, `coflux` and `cofluxd` use the new address by default:

- The desktop app, `cofluxd up` and `coflux login` default to `api.coflux.yourantiandi.com`.
- A device, desktop app or `coflux` sign-in that saved the old default address now uses the new one. You stay signed in and no device needs to be added again: your account, devices and sessions are unchanged.
- A custom server address, set with `--server`, `COFLUX_SERVER_URL` or a settings file, is kept as it is.
- Sign-in, device authorization and preview sign-in pages open on the address your app or device connected to.

Port preview links keep their `*.coflux.dev` form.

## Install or update

**Mac:** install `coflux-2.17.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.17.0
cofluxd update
```

## Upgrade impact

- The server pushes the new runtime to connected devices as usual. Once a device runs 2.17.0 it reconnects to the new address by itself; there is nothing to run on the device.
- Older desktop apps, iOS builds and devices keep working through `api.coflux.dev`, only more slowly. Update them to switch.
- The center was deployed before this tag: it now serves its pages on whichever of its addresses a client used (`COFLUX_PUBLIC_URL` plus the new `COFLUX_PUBLIC_URL_ALIASES`). No schema migration.
