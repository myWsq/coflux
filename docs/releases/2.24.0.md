# Coflux 2.24.0

**Dictation chooses its speech-recognition provider: Doubao Seed-ASR or OpenAI Realtime, each with its own base URL, model and API key.**

In 2.24.0:

- **Two dictation providers.** The Speech recognition settings, on the desktop and in the iOS app, now hold one configuration per provider, Doubao Seed-ASR and OpenAI Realtime, and a switch for the one in use. Each configuration has a base URL, a model and an API key. Leave the base URL or the model empty to use the provider's default, or point the base URL at a relay or proxy of your own. Switching providers takes effect at once, and the other provider's key stays saved, so you can switch back without entering it again.
- **OpenAI Realtime transcription.** Dictation in the iOS app can use OpenAI's live transcription model (`gpt-live-transcribe` and its dated snapshots). Text appears while you speak, and the agent's recent conversation goes along as context, as it does for Doubao. Only live models are accepted, because other OpenAI transcription models return text only after you release.
- **Keys stay write-only.** As before, API keys are stored encrypted on the account and shared by its devices. They are never shown again after you save them, and you can replace or clear each provider's key on its own.

## iOS app

The iOS app is built from source and is not part of this release's downloads. This version of the source adds the provider switch and OpenAI Realtime to dictation. The dictation badge and the not-configured message now name the provider in use.

## Install or update

**Mac:** install `coflux-2.24.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.24.0
cofluxd update
```

## Upgrade impact

- The center was updated before this release. It adds migration 12, which moves the stored Doubao key into the new per-provider settings; the migration is one-way, so an older center does not start on the migrated database.
- Nothing to re-enter: an existing Doubao key keeps working, and Doubao stays the provider in use until you switch.
- Older desktop and iOS builds keep working against the updated center and still see and edit the Doubao key. Update the desktop app and the iOS app to choose a provider.
- Devices and headless hosts need no action: the runtime is unchanged apart from its protocol definitions.
