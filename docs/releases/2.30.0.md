# Coflux 2.30.0

**Coflux now connects to `api.coflux.cn`, its own ICP-registered address.**

The server, its database and the relay for remote connections have not moved: they are the same host in Beijing. Only the address changes, from the interim `api.coflux.yourantiandi.com` to `api.coflux.cn`. Both old addresses keep working.

In 2.30.0:

- The desktop app, the iOS app, `cofluxd up` and `coflux login` default to `api.coflux.cn`.
- A device, desktop app or `coflux` sign-in that saved an earlier default address (`api.coflux.dev` or `api.coflux.yourantiandi.com`) now uses the new one. You stay signed in and no device needs to be added again.
- A custom server address, set with `--server`, `COFLUX_SERVER_URL` or a settings file, is kept as it is.
- Remote connections between devices already use the relay at `derp.coflux.cn`; the server switched it before this release.

Port preview links keep their `*.coflux.dev` form.

## Install or update

**Mac:** install `coflux-2.30.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.30.0
cofluxd update
```

## Upgrade impact

- The server pushes the new runtime to connected devices as usual. Once a device runs 2.30.0 it reconnects to the new address by itself; there is nothing to run on the device. `cofluxd update` only brings the new default to `cofluxd up` and `coflux login` on headless hosts. `ptyd` is unchanged.
- Older desktop apps, iOS builds and devices keep working through their saved address. Update them to switch.
- The center was reconfigured before this tag: its primary address is `api.coflux.cn`, and it still serves its pages on whichever address a client used. No schema migration.
