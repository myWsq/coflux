# Coflux 2.21.0

**Archive a project to get it out of the sidebar without losing it, and terminals come back exactly as programs drew them.**

Until now the only way to take a project out of the sidebar was to remove it, which deletes its record and its worktrees. Separately, a terminal redrawn after you reopened a window or switched devices lost part of what was on screen: strikethrough, underline styles and colours, hyperlinks, and settings a full-screen program had made, such as its keyboard mode.

In 2.21.0:

- **Archive a project.** The project's right-click menu in the sidebar now offers Archive project where it offered Remove project. The project and its workspaces leave the sidebar and the ⌘P palette on every client of the account. Every terminal in the project is closed and its record deleted; when terminals are still running, Coflux asks first.
- **Restore or delete it from settings.** A new Archived projects section in settings lists them with Unarchive and Delete. Unarchiving brings the workspaces back without terminals. Deleting a project permanently now happens here.
- **An archived project is frozen.** While it is archived, nothing can open a workspace or a terminal in it: the desktop app, the account CLI and an agent's `coflux terminal new` are refused. `coflux project import` of its repository unarchives it, and `coflux project list` shows `archivedAt` for each archived project.
- **Terminals keep everything when they are redrawn.** The terminal engine inside each device is now libghostty-vt, the core of the Ghostty terminal. After you reopen a window, switch devices, or the device's runtime updates, a terminal keeps strikethrough, underline styles and colours, blinking and hidden text, hyperlinks, the cursor shape, the scroll region, the Kitty keyboard protocol and other modes a program set, and tab stops. Long lines rewrap correctly when the window is resized.
- **Terminal history uses about a third of the memory.** A full 5,000-line history at 120 columns takes about 6 MB instead of about 21 MB.

One known difference: a flag emoji counts as four columns in a redrawn terminal instead of two, so the rest of that line shifts two columns to the right until the program redraws it. Live output is not affected.

## Install or update

**Mac:** install `coflux-2.21.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.21.0
cofluxd update
```

## Upgrade impact

- Archiving needs an updated center. Against an older center, the desktop app keeps the remove-project menu item and the settings section says the server does not support archiving.
- Self-hosted centers: this version applies schema migration 10 at startup, which adds a project's archive time. It is one-way: an older server refuses to start on the migrated database. Back up the database before you deploy.
- Archiving deletes the project's terminal records, including terminals that already exited. Unarchiving does not bring them back.
- The new terminal engine reaches a device with its runtime: headless hosts that run the launcher receive it automatically, and Coflux.app brings it for the Mac it runs on. Open terminals keep running through the update.
- The iOS app hides archived projects starting with its next TestFlight build.
- Building the runtime from source now requires Zig 0.17.x.
- The bundled Claude Code plugin is now 0.25.1.
