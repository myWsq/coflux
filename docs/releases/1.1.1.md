# Coflux 1.1.1

**Shell aliases no longer bypass the Claude Code and Codex integration.**

Coflux 1.1.0 skipped its managed shell wrapper whenever `claude` or `codex` was already an alias. A common alias such as `alias codex='codex --yolo'` therefore started Codex without Coflux session hooks or workspace context. This release keeps such aliases working and routes them through the integration.

## Highlights

- **Self-referencing aliases keep their arguments.** In zsh and bash, an alias that expands to the same command name, for example `alias codex='codex --yolo'` or `alias claude='claude --resume'`, now expands into the Coflux wrapper with its arguments. The alias itself is left exactly as you defined it.
- **Other aliases and functions still take precedence.** An alias pointing to a different executable and any user-defined `claude` or `codex` function bypass the wrapper as before. In fish, an alias is a function and keeps precedence.
- **No change to launch behavior.** `coflux agent run claude -- ...`, `coflux agent run codex -- ...` and `COFLUX_AGENT_INTEGRATION=off` behave as in 1.1.0.

## Install or update

**Mac:** install `coflux-1.1.1-arm64.dmg` or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:** update both the npm launcher and installed device binaries:

```sh
npm install -g cofluxd@1.1.1
cofluxd update
```

## Activation

The shell wrapper is written by the terminal runtime, so this fix needs a runtime restart: finish active work first, because a Supervisor restart ends its terminal processes. On headless devices, use `cofluxd restart` after updating; on desktop, use the runtime restart action when your tasks are finished. Then open a new terminal. Worker-only hot upgrades do not update the shell wrapper.

Shells opened before the restart keep the previous wrapper; `coflux agent run codex -- --yolo` works there in the meantime.
