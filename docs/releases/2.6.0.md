# Coflux 2.6.0

**A browser tab inside the editor groups, whose `localhost` is the workspace's own device.**

The desktop app and the runtime change; the center does not. Update the runtime on remote devices first: a remote workspace's browser tab can only reach its device's `localhost` once that device runs the 2.6.0 worker, which arrives by the usual hot upgrade.

## Highlights

- **Browser tabs next to your terminals.** A web page can now sit in any editor group, beside or below a terminal. Browser tabs share the tab strip with terminals: drag them between groups, split them off, close them with Command-W, cycle with Command-[ and Command-]. The toolbar follows Cursor's in-editor browser: back, forward, reload, an address bar with history and bookmark suggestions and a star to bookmark the page, a Console button that docks DevTools inside the tab, and a menu with visible and region screenshots (straight to the clipboard, ready to paste into an agent's terminal), copy URL, open in the system browser, hard reload, zoom, a bookmarks bar, and clearing history, cookies, cache and trusted certificates. A blank tab lists the workspace's forwarded ports. With the focus in a page, Command-L focuses the address bar, Command-R reloads the page only, Command-Option-I toggles DevTools, and Command-Plus, Command-Minus and Command-0 zoom the page.

- **The plus button asks what to open.** The plus at the end of a tab strip now offers Terminal or Browser. Command-T still opens a terminal directly.

- **`localhost` means the workspace's device.** In a browser tab, `localhost`, `127.0.0.1`, `[::1]` and `0.0.0.0` reach the machine the workspace lives on. For a remote workspace the traffic goes straight to that device over the existing encrypted device connection, never through the center, so the page keeps its real `http://localhost:<port>` origin and hot reload works. Everything else loads from this Mac, through your system proxy when one is set. If the device is offline, nothing listens on the port, or the device's runtime is older than 2.6.0, the tab says which.

- **Each workspace has its own browsing data.** Cookies, storage and cache are kept per workspace and survive restarts, so two worktrees serving the same port keep separate logins. Bookmarks and history are shared across workspaces on this Mac. Browser tabs and their addresses come back after a restart.

- **Terminal links open with a plain click.** Clicking a URL in a terminal opens it in the system browser; Command is no longer needed. Right-click a link for Open in System Browser, Open in Built-in Browser and Copy Link. Dragging a selection across a link does not open it. File references such as `src/app.ts:12` still need Command-click to copy.

- **Ports menu.** Clicking a forwarded port still opens it in the system browser; the new button at the end of each row opens it in a browser tab instead.

## Install or update

**Mac:** install `coflux-2.6.0-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux and other headless machines:** the worker upgrades itself from the release; no action is needed. To update the command-line tools as well:

```sh
npm install -g cofluxd@2.6.0
cofluxd update
```

## Upgrade impact

- **Terminal links changed behaviour:** a plain click now opens a URL. If you relied on clicking a link just to focus the terminal, click beside it.
- The device protocol gains loopback-tunnel messages. The change is additive and needs no version bump; older workers answer them with an error that the desktop shows as "this device's runtime is too old". Workers too old to speak the current remote transport at all look offline to the browser tab.
- Pages in browser tabs get no camera, microphone, location or notification permissions.
- The center is unchanged; no deployment is needed.
