# Coflux 2.5.0

**Terminals split side by side, a headless machine joins with one command, and sign-in is redesigned for GitHub and Google.**

The desktop app, the runtime, the command-line tools and the center all change. The center must be deployed first: it carries two schema migrations, and the new desktop and `cofluxd` rely on it.

## Highlights

- **Split terminals into editor groups.** Terminals now live in groups that tile left, right, up and down, nested as deep as you like, the way editor groups work in VS Code. Each group has its own tab strip. Command-Backslash splits the focused group to the right with a new terminal; Command-Shift-Backslash splits downward. Drag a tab to another group's strip to move it there, or onto an edge of a group to split it off; drag the line between groups to resize, double-click it to even the split. Moving a tab never restarts or redraws its terminal. The layout is remembered per workspace on this Mac, across restarts.

- **Changes moved to the top-right toolbar.** The resident Changes tab is gone from the tab strip. A Changes button next to ports and notifications shows the line counts and opens the diff over the whole main area; press it again or Escape to return to your terminals exactly as they were.

- **Adding a headless machine is one command.** The Headless route of Add device mints a one-time key that is valid for an hour and embeds it in a short prompt for an agent and in a command you can run yourself:

  ```sh
  npm i -g cofluxd && cofluxd up --server wss://api.coflux.dev/daemon --key cf_join_…
  ```

  The machine joins your account directly and the dialog turns to "online" on its own. Nothing is pasted back any more. A used, expired or replaced key makes `cofluxd up` stop within seconds with the reason. `cofluxd up` without `--key` still prints an authorization link for a browser, as before.

- **A new sign-in page, ready for GitHub and Google.** The desktop login screen, the device authorization page, the port-preview gate and `coflux login` share one centred design. When the center has GitHub or Google configured, those buttons appear first and sign in through the system browser; `coflux login` without flags opens the browser too, with a paste code for SSH sessions. Email and password keep working everywhere. With no provider configured, which is the state right after this deployment, only the password form is shown.

## Install or update

**Mac:** install `coflux-2.5.0-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon. The in-app update keeps the live runtime; nothing in this release needs a runtime restart on a Mac.

**Linux and other headless machines:** new machines use the command from Add device. An existing machine only needs an update if you want its `cofluxd` to understand `--key`:

```sh
npm install -g cofluxd@2.5.0
cofluxd update
```

## Upgrade impact

- **Deploy the center before anything else.** It adds schema migrations 7 (`auth_identity`, sign-in identities; `users.password_hash` becomes nullable) and 8 (`device_join_keys`). **Both are one-way**: an older center refuses to start against the migrated database, so back the database up before deploying.
- Until the center is deployed, the new desktop app cannot mint join keys (Add device → Headless shows "failed to generate a key") and the redesigned sign-in shows the password form only.
- GitHub and Google sign-in stay off until the center is configured with their client ids and secrets, a signing secret and a sign-up allowlist; see the deployment guide.
- **Command-1 through Command-9 changed meaning:** they now focus the Nth group. Selecting the Nth tab of the focused group moved to Command-Option-1 through Command-Option-9, and Command-Option with an arrow key moves between groups.
- Opening a workspace takes control of the terminal shown in each of its groups, where it used to take only the single visible one.
- The protocol changes are additive and need no version bump. A `cofluxd` from 2.4.x keeps joining through authorization links; a 2.5.0 `cofluxd --key` against a center that has not been deployed says the server does not support keys yet.
