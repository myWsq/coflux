# Coflux 1.2.0

**Terminals you can hand back to, a built-in executor for mechanical work, and notifications that stay.**

An agent working in a Coflux terminal can now open a real interactive shell and hand it to you when only a human can continue, delegate a bounded sub-task to a sandboxed executor instead of burning its own context, and reach you through a notification that survives restarts and follows your account across devices.

## Highlights

- **One kind of terminal: a real interactive shell.** Every Coflux terminal is the workspace's login shell on a real tty, alive until `exit` or an explicit close. Colours, progress bars and full-screen TUIs work, and you can take over at any time. Agents drive it the way Terminal.app is scripted: `coflux terminal new --cmd=...` types a command into a ready shell, `run` sends another one, `wait` blocks until that command finishes and prints its exit code, `read` returns the tail of the full scrollback, and `close` ends it. The separate job terminal, which piped one command's output and exited with it, is gone.
- **Hand a sub-task to the built-in executor.** `coflux executor run --prompt="Fix every clippy warning in crates/worker" --write` gives an agent a one-shot helper for mechanical, verbose work. It runs inside the desktop app under a kernel sandbox: only the originating workspace is writable, Git metadata stays read-only so it never commits, and its tool processes have no network. Configure the provider, model and API key once in the desktop settings page; without a configured model the command says so in one line.
- **A settings page in the desktop app.** Account and application settings moved out of the account menu into their own page, laid out the way Cursor does it, with the executor configuration as its first section.
- **Notifications that persist.** `coflux notify` now writes to a durable, account-owned inbox instead of a transient annotation. The fixed top-right toolbar has a bell with an unread dot and a newest-first history across all your devices and workspaces. Clicking an item marks it read and selects the terminal it came from; read state syncs between clients. A new notification shows an in-app hint when Coflux is in the foreground and a native system notification when it is not, and clicking that activates the app on the source terminal. Reconnecting replays history without a burst of alerts.
- **Move a terminal into the workspace you chose.** `coflux workspace enter <path>` migrates the current terminal's owning workspace without restarting the shell or losing the conversation, which gives Codex the equivalent of Claude's worktree entry. Managed Codex sessions remember the selection across compaction and resume, so the original host directory cannot silently pull the terminal back.
- **Coflux appears in Codex's own skill list.** Starting the interactive Codex TUI from a Coflux terminal registers an invocation-local skill root, so Coflux is discoverable and selectable natively without installing a global skill. Native profile behaviour and resume permissions are unchanged.
- **The runtime keeps its lock while it serves.** A Supervisor that was serving terminals could release its runtime lock early; it now holds the lock for as long as it serves, which closes a window where a second runtime could start alongside it.

## Install or update

**Mac:** install `coflux-1.2.0-arm64.dmg` or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:** update both the npm launcher and the installed device binaries:

```sh
npm install -g cofluxd@1.2.0
cofluxd update
```

For a new device, run `cofluxd up` and follow the authorization link.

## Activation and upgrade impact

**Restart the runtime.** This release changes the Supervisor and its shell integration, so the new terminal behaviour arrives only after a runtime restart. Finish active work first: restarting the Supervisor ends the terminal processes it owns. On headless devices run `cofluxd restart` after `cofluxd update`; on desktop use the runtime restart action. Then open a new terminal. Shells opened before the restart keep the previous integration, and worker-only hot upgrades do not update it.

**Agents see a changed terminal contract.** Terminals no longer run a command and exit on its behalf. Agents that relied on that shape should use `new --cmd` plus `wait` instead. The skill shipped with the device integration already describes the new model, and an agent relaunched after the runtime restart picks it up.

**The central server must run this version for the inbox.** Durable notifications add a schema migration and new client commands. Against an older server, sending a notification fails explicitly rather than silently falling back to the previous transient behaviour.

**The executor needs a model and a desktop.** It runs in the desktop app's sandboxed helper process, so it exists only on the machine running that app, and a run ends if the app quits or its terminals are stopped. Configure provider, model and API key in desktop settings before an agent reaches for it.
