# Coflux 2.22.0

**Agents now report their own status, so any agent that speaks the Program Status Protocol shows what it is doing, and a program that stops on an error tells you.**

Until now Coflux only knew a terminal ran an agent when the process was literally named `claude` or `codex`, and only knew its turn state through the Claude plugin's hooks. Coflux now reads the Program Status Protocol (OSC 7501), the in-band status report that agents send to their terminal, and answers the terminal's support probe so agents turn reporting on.

In 2.22.0:

- Any program reporting OSC 7501 appears as an agent in the sidebar, the tab strip, the command palette and desktop notifications, under the name it reports. This covers Claude Code 2.1.295 and later, pi 1.1.0 and later, Grok Build, Crush, and Codex builds that emit it, with no per-agent setup.
- A new state, stopped on an error, shows in red and raises a desktop notification, like waiting for approval or for an answer. It also counts toward the Dock badge.
- The one-line message an agent sends with its status appears under the workspace in the sidebar and in the notification, for approvals as well as questions and errors.
- The status clears when the program returns to your shell prompt, when the terminal is reset, or when the terminal closes.
- It also works for an agent running over `ssh` inside a Coflux terminal, since the status travels with the terminal output.

## Hooks no longer report status

Turn state now comes only from the agent itself. The Claude plugin (0.26.0) and the agent integration Coflux sets up no longer register hooks whose only job was turn state; the remaining hooks keep doing what they did: session coordinates, following the agent into worktrees, the worktree removal guard, and the session id behind the transcript view.

Agent versions that do not report OSC 7501, such as Claude Code before 2.1.295 or Codex builds without it, still appear in the sidebar when they run, but show no turn state. Update the agent to get status back. Codex asks once to trust the changed hook entries.

## Install or update

**Mac:** install `coflux-2.22.0-arm64.dmg` from `https://dl.coflux.dev/desktop/coflux-arm64.dmg`, or use the desktop app's update action. The desktop app requires macOS 26+ and Apple Silicon.

**Linux or headless hosts:**

```sh
npm install -g cofluxd@2.22.0
cofluxd update
```

## Upgrade impact

- Status is read on the device that runs the agent. On a Mac, update the desktop app. A headless host that already runs the launcher receives the new runtime automatically, with terminals kept open; `cofluxd update` does it immediately. Agents already running pick up status reporting the next time they start.
- The center was updated before this release so it accepts the new error state. No migration and no configuration change.
- A desktop app older than 2.22.0 shows an agent stopped on an error without a state.
