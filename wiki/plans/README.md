| [One executor implementation, started by whoever has a runtime](20260921-executor-daemon-host.md) | DONE, merged into main (2026-09-21, `00e9d99e`); not released. The executor is now one package, `@coflux/executor`, that the daemon hosts through a `node` child (worker-spawned, **no** `kill_on_drop`; it drains on stdin EOF and a successor waits on a lock, so a hot upgrade no longer turns running tasks into `Unknown`) and that Coflux.app hosts in its main process from the same published files. Which one hosts is an explicit `HostAuthority` election — a daemon host refuses a client one and may take over from it — never epoch arbitration. Delivery is npm rather than a fifth signed binary: measured 2026-09-21, `bun build --compile` output cannot be codesigned at all, and a stock runtime binary would need its own JIT entitlements (6-7x slower, silently, without them) plus roughly ten changes that each assume a single companion artifact. Every automated gate green: desktop typecheck + 272/272 tests + build, server typecheck, zero-warning `cargo build --workspace`, `COFLUX_HOME= cargo test -p coflux-worker` 142/142, black-box 58/58, plugin sync clean. Delivery is self-contained: `@coflux/executor` is workspace-internal and marked `private`, and cofluxd's `prepack` bundles its host and runner into the tarball with esbuild (35K + 14K, pi left external), so `npm i -g cofluxd` resolves only pi from the registry — no second package, no Trusted Publisher binding, no publish order. Verified by packing: the tarball carries `executor/host.js` and `executor/runner.js`, declares only pi, and has no `workspace:` specifier left in it. npm's own `bundleDependencies` would have been the native mechanism but pnpm refuses it under `nodeLinker: isolated`. **Pending the user**: the real-machine walkthrough (Coflux.app with the bundled daemon — exactly one host registers and a task runs). Linux registration stays off until the sandbox plan lands | subagent opus | None; M1 gates all, M2 and M3 are independent (disjoint paths, meeting only at the environment variable names M1 fixes), M4 needs both |
